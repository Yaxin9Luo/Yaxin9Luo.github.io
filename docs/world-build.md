# Build and publish the website

The whole site is the Vite app in `world/`. `npm run build:site` (`scripts/build-site.mjs`) assembles the static output in `dist/`:

- `/`: the Editable Canvas homepage, with the optional 3D academy behind it.
- `/blog/` and `/blog/<slug>/`: the blog and one page per published post.
- `/yuanmingyuan.html`: the Yuanmingyuan museum.
- `/files/`, `/images/` and `/Yaxin.JPG`: public academic files copied from the repository root (CV PDFs, editable resumes, paper figures, portrait).
- `/og/`: share preview cards (`world/public/og/`, generated by `scripts/og/`).
- Redirect pages for every page path of the removed Academic Pages site, both at the old root URL and under `/traditional/` (`scripts/site/legacy-redirects.json`).
- `404.html` (`scripts/site/404.html`), which also forwards unknown `/traditional/…` URLs, and a fresh `sitemap.xml` listing the homepage, the blog and each published post.

## Local build

Use Node.js 22.12 or newer. The app dependencies are pinned by `world/package-lock.json`; the root has no dependencies.

```sh
npm --prefix world ci
npm run build:site
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

The build syncs `_data/portfolio.json` from `world/src/content.js`, builds the app, verifies the pinned external 3D asset bytes (`scripts/prepare-public-assets.mjs`), then assembles `dist/`. It fails if an essential page, a CV PDF, a paper figure, a share card or a redirect target is missing, if a redirect would overwrite a site file, or if the app or blog still links to `/traditional`. `SITE_URL` may override the canonical hostname; the default is `https://yaxin9luo.github.io`.

`node scripts/build-site.mjs --skip-app` reassembles `dist/` from an existing `world/dist/` without rebuilding the app, which is handy when only the redirects, 404 page or sitemap change.

## Branch and deployment behavior

`.github/workflows/world-site.yml` builds the site for pull requests, pushes to `master` and manual runs. Pull requests and feature-branch manual runs cannot deploy. The deployment job runs only for a push to `master`, or a manual run on `master` with the `deploy` input selected.

The workflow follows [GitHub's custom Pages workflow contract](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages): it uploads a static Pages artifact, and grants `pages: write` and `id-token: write` only to the deployment job.

## Verification scope

The build checks above do not replace browser checks. Before publishing, open the English and Chinese homepage, the blog, a post page, the 404 page and a few legacy URLs (for example `/publications/`, `/cv/` and `/traditional/zh/`) over the local HTTP server.
