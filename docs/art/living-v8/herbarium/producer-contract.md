# Herbarium producer contract

The original architecture and garden composition are authored in `world/src/herbarium-assets.js`. The model's long local axis is X, its front is +Z, and its finished walkable floor is local y=0. Foundations extend below that datum. Generated reference PNGs are aesthetic targets only.

Runtime constructors return a `THREE.Group`: `createArcade({bays:4})`, `createConservatory()`, `createWaterGarden()`, and `createGardenBorder({length:12,seed:81})`. Call and await `loadHerbariumAssets({deadline,signal,onProgress})` during the progressive asset phase before constructing the production groups. It loads shared physical texture channels plus the accepted fern_02, periwinkle_plant and potted_plant_01 GLBs; failure is explicit and retryable. Each caller retains its own deadline, abort signal and progress callback through the existing resource coordinator; a cancelled caller cannot cancel another active caller. The deadline is an absolute `performance.now()` value, not a duration. Already aborted/expired calls reject even when resources are cached. Planted constructors require those prototypes and fail clearly if the preload was omitted. The rejected shrub is retained only in research evidence, outside public/runtime assets. Each main group lists actual CC0 source hashes and names in sourceAssets metadata. Fern a/b and periwinkle04 are selected source variants; the complete potted tree preserves all authored node transforms. Lower planted collections reuse its original pot/pebble geometry with explicit substrate part provenance.

Use `cloneHerbariumAsset(group)` for another transform of an existing kit instance. That helper gives independent transform and metadata objects while retaining the geometry owner. Pair each group with `disposeHerbariumAsset(group)`: it removes that instance and disposes geometry only after the last registered clone. Materials and textures belong to the shared asset layer and are never disposed by an individual group. An unregistered `group.clone()` must not be used as an independently disposable instance.

Metadata includes advertised dimensions, measured actual bounds, each batch's named triangle index ranges, local solid collider bounds, support mesh names, authored clear-passage volumes and plant-root positions. `getHerbariumColliders(group)` transforms actual named local solid boxes to world AABBs; it deliberately does not turn the greenhouse's whole envelope into an obstacle. The water basin is a pool obstacle. `getHerbariumSupportGeometries(group)` returns caller-owned transformed geometry copies from the exact rendered floor/sitting-shore meshes. Feed those to `createSurfaceSupport.addGeometry`, then dispose the copies. Water surfaces are excluded from walking support. Task 3 owns grade transitions, terrain/grass masking, collision-plane adaptation and actual traversal.

The required clear volume is at least 2.2 wide and 3.6 high over the full rectangular width. Actual triangle intersection tests cover the arcade aisle/south bays, greenhouse entry/central aisle, and water garden east arrival. Player height3.28 controls vertical clearance. Elizabeth walk width1.98444/top3.02751 and Sadaharu walk width1.68807/top3.00065 fit that same reserved volume. Elizabeth's wider sign interaction requires outdoor space in Task5.

The isolated studio uses the native device pixel ratio and 4096 shadow map. It provides neutral/day/night, overview/close/side/character-eye/interior views, a separately labeled3.28m mannequin, geometry mode and native PNG plus metadata capture. The local capture endpoint writes to `work/production-v3/captures`. Root owns browser and visual acceptance. Its source snapshots identify candidates; version8 alone is not a candidate identifier.

## Task3 loading and integration

Production consumers import the constructors and helpers from `world/src/herbarium-assets.js`. `loadHerbariumAssets` fetches only `/models/herbarium/botanical/fern_02.glb` (18,738,904 bytes), `periwinkle_plant.glb` (22,202,628 bytes), `potted_plant_01.glb` (35,796,560 bytes), and the existing castle-masonry/oxidized-copper/aged-wood/mossy-rock PBR channels. The three botanical transfers total 76,738,092 bytes before HTTP compression, with full source 4K textures. Shared decoded resources remain cached for the page lifetime. Per-instance disposal must not free that cache.

The assembled exports are in ignored `work/living-v8/exports/herbarium/`, outside public/Git; recipes and final hashes are tracked. The assembled `arcade.glb`, `conservatory.glb`, `water-garden.glb`, `flower-border.glb` and their `.blend` files are portable/export deliverables; the constructors do not download them. Avoid fetching both assembled exports and source packages for the same runtime composition. The assembled exports require the standard Meshopt and lossless WebP extensions; `gltf-resource.js` already configures the required Meshopt decoder. `world/public/models/herbarium/manifest.json` gives final file sizes and source/export identity. Full artifacts are locally available at `http://127.0.0.1:4234/work/living-v8/exports/herbarium/` and reproducible with `node world/scripts/export-herbarium-assets.mjs`.

Preload during the progressive asset phase, await success, then construct/place groups. There is no hidden asynchronous mutation after construction: geometry is complete when a constructor returns. A staged scene that already constructed the unplanted arcade can use the shared material objects, which bind their maps when preload completes; planted constructors require prepared source prototypes and fail clearly otherwise. Keep loading/retry status visible, pass the scene lifetime AbortSignal and absolute deadline, and discard obsolete scene work before construction. On a failure, retry `loadHerbariumAssets`; successful partial resources are reused. There is no silent placeholder or fallback species.

The default complete kit contains 34,390 arcade, 2,598,090 conservatory, 833,808 water-garden and 388,036 border triangles, in 6/13/18/5 material batches. Counts preserve all accepted source geometry and authored detail; clone reuse avoids rebuilding identical geometry. The constructors allocate complete static geometry on the main thread, so call once per required design and use `cloneHerbariumAsset` for repeats. Low-spec performance and final integrated world rendering remain Task3/whole-world review responsibilities; no world-wide resolution or geometry reduction is applied here.

Use each helper after setting the group's final position/rotation/parent; they flush world matrices themselves. Support copies must be added to the support system and disposed after ingestion. Collider boxes are conservative world AABBs around named solids. The consumer should adapt their vertical span and semantics to its collision system, preserving the clear central passages and water obstacle. Editable Blender imports map runtime X/Y/Z to Blender X/Z/−Y; the export audit maps coordinates back before comparing actual bounds.
