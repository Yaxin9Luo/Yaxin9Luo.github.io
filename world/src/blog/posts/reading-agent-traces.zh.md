长任务的 Agent 跑起来容易，事后读起来难。下面是我读轨迹的顺序。

## 第一遍：看结尾

先读最后二十步。Agent 停下来，是因为做完了、放弃了，还是它*以为*自己做完了？第三种最常见，也最有用。

## 第二遍：看任务清单

如果 Harness 维护了清单，就按时间对比它的变化。先打勾、后来又取消的项，就是 Agent 发现自己错了的地方。

## 第三遍：找第一个错误的转折

在轨迹里二分查找，找到第一个你会否定其输出的步骤。之后的问题通常都是它的连锁反应。

> [!TIP]
> 从第一个工具报错开始找是个好起点，但第一个*错误*的步骤，常常是一次参数不对、却执行成功的工具调用。

## 第四遍：它没看过什么

列出 Agent 本可以读、却没有读的文件和文档。缺上下文导致的失败，比推理错误导致的更多。
